## 주요 변경

- **업데이트 직후 데이터베이스 오류 수정**: 1.0.28로 처음 실행할 때 데이터가 많으면 DB 백업·마이그레이션이 창이 뜨기 전에 오래 걸려 멈춘 것처럼 보였습니다. 이때 앱을 다시 실행하면 두 번째 실행이 같은 마이그레이션을 또 적용하다 `index idx_images_file_path already exists` 오류를 띄웠습니다. 이제 두 번째 실행은 DB를 건드리지 않고 기존 창을 앞으로 가져오며, 다른 프로세스가 이미 적용한 마이그레이션은 다시 실행하지 않습니다.
- **백업 폴더 정리**: 백업 도중 앱을 강제 종료하면 DB 크기만 한 임시 파일(`.tmp`)이 `backups` 폴더에 남아, 실행할 때마다 쌓이며 디스크를 채웠습니다. 이제 앱을 실행할 때마다 남은 임시 파일을 정리합니다. 1.0.28에서 이미 쌓인 파일도 1.0.29를 처음 실행할 때 지워집니다.

## 기존 사용자 데이터

이번 버전은 데이터베이스 스키마 **v20을 유지**합니다. 1.0.28에서 위 오류를 본 경우에도 마이그레이션은 트랜잭션으로 실행되어 작업 데이터는 그대로 남아 있습니다. 1.0.27 이하에서 바로 업데이트하면 v18에서 v20으로 올라가며, 업그레이드 전에 기존 DB가 자동 백업됩니다. 첫 실행은 데이터 양에 따라 시간이 걸릴 수 있으니 창이 뜰 때까지 기다려 주세요.

## 다운로드

- Windows x64: `nais3-1.0.29-setup.exe`
- Mac Apple Silicon: `nais3-1.0.29-arm64.dmg`
- Mac Intel: `nais3-1.0.29-x64.dmg`
- Linux x64: `nais3-1.0.29-x86_64.AppImage` (Ubuntu 22.04 이상은 `libfuse2` 필요)

Mac ZIP과 Windows·Linux 업데이트 메타데이터는 앱 내 자동 업데이트에 사용됩니다.

## Highlights

- Fixed a database error after updating: on large workspaces the first 1.0.28 start (backup plus index migration) ran before any window opened and looked hung, and launching again re-applied the same migration and failed with `index idx_images_file_path already exists`. A second launch now only focuses the existing window, and a migration applied by another process is never run twice.
- Snapshot temp files left in `backups/` by a launch killed mid-backup are now removed on every start instead of accumulating, including files already piled up under 1.0.28.

Database schema stays at **v20**. Users who saw the error on 1.0.28 keep their data, since each migration runs in a transaction. Upgrading from 1.0.27 or earlier still moves v18 to v20 with an automatic backup first; the first start can take a while on large workspaces.
